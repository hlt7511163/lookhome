## 补丁一：contracts 表增加 contract_text 列（必须）

审核通过签约时要生成合同文本快照，代码会写入 `contracts.contract_text`。**若该列不存在，管理员点「通过」会报 500「table contracts has no column named contract_text」**——这是上游代码与建表 SQL 不一致导致的缺口。

先检查列是否已存在：

```bash
# MySQL
mysql -u root -p -e "USE lookhome; SHOW COLUMNS FROM contracts LIKE 'contract_text';"

# SQLite
sqlite3 data/lookhome.db "PRAGMA table_info(contracts);" | grep contract_text
```

无输出则执行补列：

```bash
# MySQL
mysql -u root -p -e "USE lookhome; ALTER TABLE contracts ADD COLUMN contract_text LONGTEXT NULL;"

# SQLite
sqlite3 data/lookhome.db "ALTER TABLE contracts ADD COLUMN contract_text TEXT;"
```

顺带确认 `lease_applications.agreed_at` 已存在（11 月 8 日已加过，复查即可）：

```bash
mysql -u root -p -e "USE lookhome; SHOW COLUMNS FROM lease_applications LIKE 'agreed_at';"
```

## 补丁二：settings 支持合同模板（server/routes/settings.js）

小程序「我的 → 合同模板」页依赖这两个能力：GET 能读出模板、PUT 能写入模板。共三处小改：

**① GET 响应中增加 `contract_template` 字段**（主管理员分支的 `res.json({...})` 内，`wechat_mini` 块之后加一行）：

```js
    wechat_mini: {
      appid: data.wechat_mini_appid,
      // ...原有内容不动
    },
    contract_template: data.contract_template || '',   // ← 新增
```

**② ALLOWED 白名单增加 `'contract_template'`**：

```js
const ALLOWED = new Set([
  'site_name', 'site_logo', 'site_icp', 'site_url', 'site_phone',
  'realname_verify_mode', 'payment_confirm_mode',
  'contract_template',          // ← 新增
```

**③ PUT 改为 upsert**（原实现是 `UPDATE settings SET value=? WHERE key=?`，新 key 首次保存会静默丢失——`updated` 计数照涨但一行都没写进去。合同模板作为新 key 必须改成 upsert）：

```js
r.put('/', auth, adminOnly, (req, res) => {
  const body = req.body || {};
  // upsert：新键（如 contract_template）首次保存时自动插入，旧键更新
  const stmt = db.prepare('INSERT INTO settings (key, value) VALUES (?, ?) ON CONFLICT(key) DO UPDATE SET value=excluded.value');
  let n = 0;
  for (const [k, v] of Object.entries(body)) {
    if (ALLOWED.has(k) && v !== undefined) { stmt.run(k, String(v)); n++; }
  }
  res.json({ ok: true, updated: n });
});
```

> MySQL 8.0.19+ 才支持 `ON CONFLICT ... DO UPDATE` 语法。若你的 MySQL 版本较老，用等价写法：
> `INSERT INTO settings (key, value) VALUES (?, ?) ON DUPLICATE KEY UPDATE value = VALUES(value)`
> （settings 表的 key 列需有唯一索引：`ALTER TABLE settings ADD UNIQUE KEY uk_key (key);`，若已存在忽略）
> SQLite 3.24+ 原生支持 ON CONFLICT，better-sqlite3 内置版本满足。

**重启服务**后验证：

```bash
curl -s -H "Authorization: Bearer <管理员token>" http://127.0.0.1:3000/api/settings | grep -o '"contract_template":"[^"]*"'
# 应输出 "contract_template":"" 或已保存的模板内容
```

## 补丁三：微信支付 paySign 五件套（server/routes/pay.js）

`/api/pay/jsapi` 原来把微信下单接口的原始响应直接丢给前端，里面只有 `prepay_id`，小程序 `wx.requestPayment` 无法使用。需要在服务端用商户私钥做二次签名，返回五件套。

**改动位置**：`r.post('/jsapi', ...)` 里 `fetch(...).then(async wx => {...})` 的成功分支，把原来的：

```js
    // 保存订单号，回调后核对
    db.prepare(`UPDATE bills SET pay_trade_no=? WHERE id=?`).run(outTradeNo, bill.id);
    res.json({ mode: 'wechat', pay_params: data, out_trade_no: outTradeNo });
```

替换为：

```js
    // 保存订单号，回调后核对
    db.prepare(`UPDATE bills SET pay_trade_no=? WHERE id=?`).run(outTradeNo, bill.id);
    // 计算小程序 wx.requestPayment 五件套（对 appid\ntimeStamp\nnonceStr\npackage\n 做 RSA-SHA256 二次签名）
    const payTs = Math.floor(Date.now() / 1000).toString();
    const payNonce = crypto.randomBytes(16).toString('hex');
    const payPkg = 'prepay_id=' + (data.prepay_id || '');
    const paySign = crypto.createSign('RSA-SHA256')
      .update(`${CFG.appid()}\n${payTs}\n${payNonce}\n${payPkg}\n`)
      .sign(CFG.privateKey(), 'base64');
    res.json({
      mode: 'wechat',
      pay_params: { timeStamp: payTs, nonceStr: payNonce, package: payPkg, signType: 'RSA', paySign },
      out_trade_no: outTradeNo
    });
```

> `crypto` 该文件顶部已引入；`CFG.privateKey()` 读的是 settings 的 `wechat_pay_private_key`。
> 注意消息串结尾有一个换行 `\n`，四个字段各一行，与微信官方文档一致。

## 补丁四：微信支付/小程序配置（Web 后台「系统设置」）

打齐三个代码补丁并重启后，在 Web 后台系统设置里配置：

| 配置项 | 说明 |
|---|---|
| `wechat_mini_appid` | 小程序 AppID（与 project.config.json 一致） |
| `wechat_mini_secret` | 小程序 AppSecret |
| `wechat_pay_mchid` | 微信支付商户号 |
| `wechat_pay_apiv3_key` | APIv3 密钥（32 位） |
| `wechat_pay_serial_no` | 商户证书序列号 |
| `wechat_pay_private_key` | 商户私钥（apiclient_key.pem 文件全文，含首尾行） |
| `wechat_pay_notify_url` | 支付回调地址，须为 `https://域名/api/pay/notify` |
| `wechat_pay_platform_pubkey` | 微信支付平台公钥（验签用；不配则拒绝所有回调，防伪造入账） |

配置不完整时系统自动降级为「手工确认收款」（前端弹线下转账指引），不影响签约审核等其余流程。

## 追加：工作台指标改两行两列 + 推送账单给租客（2026-11-11）

### 1. 工作台指标卡布局

- 原来 4 张指标卡是「一行一张」竖排：`.stat-card` 用 `width: calc(50% - 24rpx)` 且没有 `box-sizing: border-box`，`padding 56rpx + margin 24rpx` 让每张卡实际超过 50% 宽度，`flex-wrap` 只能换行成单列；且 `calc()` 里混 `rpx` 在部分基础库下不生效（宽度退化成 auto，同样会单列）。
- 改法：新增 `.stat-cell` 包裹层，`width: 50% + box-sizing: border-box + padding: 12rpx` 负责间距，卡片本身不再算宽度。彻底不用 `calc()`，两行两列稳定。

### 2. 推送账单给租客

| 项 | 说明 |
|---|---|
| 入口 | 管理端「账单」tab 顶部工具栏「📢 一键推送」；单张账单卡片右侧「推送」按钮；工作台「待办提醒」新增「📢 推送账单给租客」（跳到账单 tab） |
| 接口 | `POST /api/reminders/manual`，body `{ bill_ids: [...] }`，返回 `{ ok, created, skipped, denied }` |
| 租客侧效果 | 写入 `reminders` 表 → 租客端「消息」tab 显示「房东催缴」；点开可跳该账单 |
| 微信通知 | 服务端同时调 `sendToTenant(tenant_id,'pay',...)` 订阅消息。**只有当租客点过订阅、且后台配了「账单缴费」模板 ID（`wechat_template_pay`）时才真的收到微信服务通知**；否则只在 App 内消息里可见 |
| 去重 | 同一账单同一来源（manual）只提醒一次，重复推送会被服务端记为 `skipped` |
| 权限 | 操作员仅能推授权项目下的账单，越权计 `denied` |

推送结果页会回报「已推送 N 条 / M 条此前已提醒 / K 条无权操作」，服务端错误（如 500）原样弹窗。
